## The problem

Any endpoint that moves money or state has to survive a client retry. Networks drop responses, users double-click, workers restart. Without a guard, every retry is a chance to charge someone twice.

## The fix is old and dull

The client sends a key with the request. The server stores the result under that key, and a unique index makes the second insert a no-op.

```sql
INSERT INTO requests (key, response)
VALUES ($1, $2)
ON CONFLICT (key) DO NOTHING;
```

## What to store

Store the response, not just a flag, so a repeated request gets the same answer instead of an error. Give keys an expiry so the table does not grow forever.
